# SkinLab — справочник уход-активов (прототип)

PWA-прототип, который помогает разобраться, как применять активные ингредиенты в уходе за кожей:
противопоказания, способ применения, хорошие и плохие сочетания, подходящие типы кожи, побочные эффекты.

Сделан **скелет** с красивым UI и четырьмя вариантами дизайна поверх общей логики и общей базы данных.
Реального распознавания косметики по фото пока нет — это осознанная заглушка (см. ниже).

## Запуск

```bash
./start.sh
# или
python3 -m http.server 4173 --directory public --bind 127.0.0.1
```

Затем открыть **http://127.0.0.1:4173** — это хаб выбора макетов.

Прямые ссылки на макеты:

| # | Макет | Стиль | URL |
|---|-------|-------|-----|
| 1 | **Botanica** | Мобильный app-shell, спокойная ботаническая палитра, нижняя навигация, шторки | `/m1-botanica/` |
| 2 | **Editorial** | Журнальная вёрстка, крупная типографика, боковое оглавление | `/m2-editorial/` |
| 3 | **Noir Glow** | Тёмная тема, стеклянные карточки, градиентное свечение, карусели | `/m3-noir/` |
| 4 | **Bubble** | Округлые пузырьки активов, яркий пастельный градиент, крупные элементы | `/m4-bubble/` |

## Что уже умеет каждый макет

- **Поиск** по названию актива и по каталогу косметических средств.
- **Сканер** — реальное превью с камеры (`getUserMedia`) + кнопка загрузки фото.
  Распознавание состава — заглушка: возвращает случайное средство из тестового каталога.
- **Карточка актива** — что даёт, как применять, кому подходит по типам кожи,
  противопоказания, побочные эффекты, сочетания (хорошие/нейтральные/осторожно/нельзя), pH, беременность.
- **Проверка сочетаний** — попарный вердикт для набора активов + рекомендованный порядок нанесения (утро/вечер).
- **Профиль** (тип кожи, «полка») сохраняется в `localStorage` и общий для всех макетов.
- **PWA**: устанавливается на телефон, работает офлайн после первого открытия.

## Структура

```
public/
  index.html               # хаб выбора макетов
  manifest.webmanifest     # PWA-манифест
  sw.js                    # service worker (офлайн-кэш)
  assets/                  # иконки PWA и локальные шрифты
  shared/                  # ОБЩИЙ слой для всех макетов
    data.js                #   база активов, правил сочетаемости и продуктов
    engine.js              #   поиск, совместимость, порядок нанесения, профиль
    content.js             #   генерация HTML карточек и блоков
    scanner.js             #   работа с камерой + заглушка распознавания
    pwa.js                 #   регистрация SW и кнопка установки
    base.css               #   сброс + общие компоненты (.sl-*)
  m1-botanica/             # макет 1 (index.html + theme.css + app.js)
  m2-editorial/            # макет 2
  m3-noir/                 # макет 3
  m4-bubble/               # макет 4
tools/                     # вспомогательные скрипты (иконки, шрифты, скриншоты)
```

Ключевая идея: **данные и логика — общие** (`shared/`), а каждый макет переопределяет
только оформление (`theme.css`) и композицию экранов (`app.js`). Это позволяет
выбрать понравившийся дизайн и дальше строить приложение, не переписывая логику.

## Бэкенд (API каталога)

Node + Fastify + SQLite (`better-sqlite3`). Сервер **переиспользует** тот же справочник
активов и логику сочетаемости, что и фронт (`public/shared/`), а в БД хранит только
каталог продуктов. Источник каталога — [Open Beauty Facts](https://world.openbeautyfacts.org)
(открытая база косметики по штрихкодам, ODbL).

```bash
npm install          # зависимости бэкенда
npm run seed         # наполнить каталог демо-продуктами из shared/data.js
npm start            # API на http://127.0.0.1:8787
npm run smoke        # быстрый прогон эндпоинтов без реального порта
```

Наполнение реальными данными:

```bash
# точечно, по штрихкодам (live API OBF: 1 запрос = 1 реальный скан)
node server/scripts/import-obf.js 8001090662231 3560070791460

# массово, из ночного дампа (правильный способ для большого каталога)
node server/scripts/import-obf.js --dump en.openbeautyfacts.org.products.csv.gz --limit 5000
```

### Эндпоинты

| Метод | Путь | Назначение |
|-------|------|------------|
| GET | `/api/health` | статус, размер каталога |
| GET | `/api/meta` | типы кожи, цели, уровни сочетаемости |
| GET | `/api/actives` | все активы справочника |
| GET | `/api/actives/:id` | актив + связи + продукты с ним |
| GET | `/api/products?q=&active=&limit=&offset=` | поиск по каталогу |
| GET | `/api/products/:barcode` | продукт; при промахе — подтяжка из OBF по скану |
| POST | `/api/analyze` | главный анализ: вход `barcode` \| `ingredientsText` \| `actives[]` + `profile` |

`POST /api/analyze` возвращает: раскрытые активы, «для чего» (цели/эффекты),
попарный вердикт сочетаний, порядок нанесения (утро/вечер), противопоказания и
персональные предупреждения под тип кожи и беременность.

```
public/shared/data.js  ──► справочник активов + правила (общий с фронтом)
Open Beauty Facts dump ──► products (barcode, brand, INCI …) в SQLite
                              │
                    INCI-матчер (server/src/inci.js)
                              │
                       analyze (engine.js) ──► API ──► фронт
```

## Что делать дальше (для реального продукта)

1. Скан на фронте: штрихкод (быстро/надёжно) + OCR состава (Tesseract/облако) как fallback,
   затем `POST /api/analyze` с `barcode`/`ingredientsText`.
2. Расширить базу активов и правил, желательно с ссылками на исследования.
3. Нарастить каталог из дампа OBF; настроить ежедневный импорт.
4. Локализация и доступность (уже частично учтена).
